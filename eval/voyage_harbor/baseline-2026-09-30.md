# Terminal-Bench 2.1 native Voyage pilot — 2026-09-30

Thirty trials completed using gpt-6.1-sol at medium, high and xhigh on the same
existing ChatGPT subscription account. Medium gave the best observed combination
of task success, clean completion, speed and tokens in this small selected subset.
This is an integration baseline, not an official leaderboard score or evidence
that medium is generally superior.

A passing verifier can coexist with a timed-out or incomplete native run. Those
outcomes stay separate. Two artifact-correct runs ended canonically incomplete despite
completion text; their readiness cause was not established. All extract-elf runs
produced 0% reference-address coverage against a required 75%. All three HTML-filter
runs encountered native provider stream/request failures at HTTP 200; their cause is
unknown and was not classified as a refusal.

The runtime removes run-owned shell descendants at finalization. Git deployment
histories observed working SSH/Nginx, but verifiers then saw SSH connection refusal.
A zero-inference HTTP-service control confirmed the service was already dead after
canonical completion and before explicit adapter Stop. Service-dependent tasks are
therefore a compatibility finding in this configuration; do not disable cleanup or
interpret those rows as pure model quality.

## Exact scope and evidence

The corrected run was `tb21-pilot-20260930-v2 / voyage-medium-high-xhigh-v2`,
2026-09-30 20:48:12–22:17:55 UTC. Harbor exited 0 after all 30 verifiers. Each task
had one attempt per effort, no Harbor retries, task-declared time/resources and
at most one concurrent trial per effort. The initial matrix was cancelled and marked
invalid because Docker exec timeout detached the native runtime; it is excluded.

The Rust source was pinned to **675f12ed1f05b03f6fc45828993f95fec8e55b85**,
not the newer main that was published during the experiment. Its downloaded public
nightly archive/checksum and binary manifest were verified. To support older task
images and the host-only credential relay, unchanged sources were compiled with
Rust 1.94.1 in Debian 12, release/locked/default features plus
`reqwest/rustls-tls-native-roots`. This local variant is not a published release.
Task dataset commit: **7131e4375048a0e408a8fb404b5f499d726b695b**.

[Machine-readable results](baseline-2026-09-30.json) retain binary hashes, frozen
adapter hashes, task image IDs/digests, resource settings, per-trial outcomes and
reported usage. The initial delivered adapter differs from the measured snapshot
by formatting/import cleanup and extra timeout Stop receipt retention; AST comparison
verified these stated differences. The subsequent normal-exit cleanup guard was not
part of the measurement; all measured trials already had observed cleanup.

All 30 native runtime cleanups were observed, Docker had no remaining containers
after controller exit, and the owned credential brokers stopped and removed their
scoped sockets/tokens. Rootless Docker remains installed as a user service. The query
container's actual cgroups showed one CPU and 2 GiB memory; IO/storage enforcement
and other native platforms are not certified. Raw traces and CA signing material
remain private on the executing PC; real account credentials never entered containers.

Offline oracle/no-op controls returned 1/0; native mock and live-medium integration
smokes returned 1. Forced deadline cleanup and normal-exit cleanup fault injection
verified that unconfirmed cleanup prevents grading. Python compileall, Ruff F/format,
source/path/link/JSON checks and Git diff checks passed. No Rust/Cargo inputs or tests
were edited, so no new Rust coverage or hosted build is attributed to this Python
adapter delivery. [Setup and rerun instructions](README.md) and
[#397](https://github.com/o-psi/helm.vessel.voyage/issues/397) retain the delivery record.
