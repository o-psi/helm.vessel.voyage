# #333 finalized protocol / Vessel contract

Source of truth: `crates/voyage-protocol/src/host_browser.rs`. This contract is
for the executing-host browser, NOT the legacy opt-in local `Browser` executor.
Worker transport is separately specified by
[worker contract](../voyage/browser/CONTRACT.md).

## Trusted transport and authority

Public `VoyageCommand::HostBrowser { operation: HostBrowserOperation }` requires
outer `VoyageRequest { session_id, incarnation: Some(observed_incarnation), command }`.
Both native and web authenticated duplex sockets support it. HTTP and direct
public IPC have no trusted socket scope and cannot translate this command.

Private `RuntimeCommand::HostBrowser { operation, socket: HostBrowserSocket }`.
`HostBrowserSocket { socket_id: Uuid }` is generated by Vessel per WebSocket.
`RuntimeRequest.authorization: Option<GrantBinding>` supplies authenticated
`principal_id`; there is no new `request.principal` field. Runtime validates scoped grant revocation/expiry and rights for every operation.
Authenticated local-owner sockets use private same-user IPC without a scoped grant;
the supervisor supplies socket provenance and never accepts it from public JSON. IDs in requests do not confer authority. Supervisor wraps an
authenticated `Granted` envelope in private `VesselCommand::Socket { socket,
command }`; HTTP/socket public input refuses private envelopes. No browser token
or principal is placed in public operation payloads.

Private disconnect:
`RuntimeCommand::HostBrowserDisconnected { socket: HostBrowserSocket }`.
Private gateway envelope:
`VesselCommand::HostBrowserDisconnected { session_id, incarnation, socket }`.
Supervisor forwards with exact session/incarnation and `authorization: None`
over same-user authenticated private IPC. This intentionally bypasses expired or
revoked grants for **cleanup only**, not execution. It must fence only attachments
previously recorded against this socket, including their original principal.
It has no public right, mutation ID, or generic public operation equivalent.

Gateway closes admission synchronously on disconnect, retains up to 32 touched
(session, incarnation) pairs per socket, and delivers notification independently of admitted browser effects. Runtime MUST keep disconnected-socket
tombstones for its lifetime, reject late admissions, and fence in-flight completion:
a timed-out IPC exchange is not proof its effect finished. Duplicate disconnect
is idempotent. Release controller and revoke signaling/capture for this socket;
never implicitly resume agent mode from private mode. Notification delivery is
bounded/best-effort, not a durable cleanup acknowledgement: gateway crash or
unreachable IPC requires runtime's separate fail-closed owner/lease mechanism.
Do not claim process liveness establishes socket liveness.

## Strict operation schema

Serde `action` tag, snake_case, unknown fields denied:

- `Status` — Observe; no mutation ID.
- `Start { command_id, expected_revision: u64, incarnation }` — Execute.
- `Attach { command_id, binding }` — Observe; caller supplies fresh non-nil attachment ID.
- `Detach { command_id, binding }` — Observe.
- `Control { command_id, binding, mode: Agent|Human|Private }` — Execute.
- `Signal { command_id, binding, signal }` — Observe.
- `Input { command_id, binding, sequence: u64, input }` — Execute; sequence > 0.
- `Receipt { command_id }` — Observe; ID queried, not new mutation.
- `Close { command_id, binding }` — Execute.

`HostBrowserBinding` (all fields required, unknown fields denied):
`{ incarnation, browser_id, attachment_id, tab_id, document_epoch: u64,
viewport_epoch: u64, controller_epoch: u64, capture_epoch: u64 }`.
All UUIDs non-nil for operations and all epochs > 0. Status may expose an unbound
binding with nil attachment_id; replace it with a fresh ID when attaching. Runtime
must validate exact live browser, tab/document/viewport/controller/capture fences,
principal and socket before effects (including signaling), not just structure.

`HostBrowserSignal` (`type` tag, strict):
- `RequestOffer` (`request_offer`): worker creates offer.
- `Answer { sdp }`: nonempty, <= 65536 UTF-8 bytes.
- `Ice { candidate, sdp_mid: Option<String>, sdp_mline_index: Option<u16> }`:
  candidate <=8192 bytes, mid <=256 bytes. Structurally accepted for typed
  compatibility; current full-ICE runtime/worker MUST refuse trickle ICE.

`HostBrowserInput` (`type` tag, strict):
- `Pointer { x: u32, y: u32, button: Option<Left|Middle|Right>, pressed: bool }`:
  x/y <=16384; runtime additionally validates live viewport.
- `Key { key, pressed }`: nonempty key <=128 bytes, no control characters.
- `Text { text }`: nonempty <=16384 bytes.
- `Scroll { delta_x: i32, delta_y: i32 }`: absolute value <=16384 (overflow-safe).
- `Resize { width: u32, height: u32 }`: width 320..3840, height 240..2160.
- `Dialog { accept: bool, text: Option<String> }`: text <=16384 bytes.
- `Navigate { url }`: <=8192 bytes, no controls, http:// or https:// prefix.
  This is structural validation only; worker/runtime must parse and enforce URL,
  origin, DNS, redirect, credential and network policy.
- `Tab { operation: New|Select|Close, tab_id: Option<Uuid> }`: New requires None;
  Select/Close require non-nil ID, independently validated by runtime.

All effect command IDs non-nil. `mutation_id`, `binding`, `valid`,
`required_right`, `is_ephemeral` helpers are available. Signal/Input are ephemeral:
use bounded attachment receipts, not durable secret payload logging. Exactly
match deduplication payloads; uncertain effects must not replay automatically.
Generic Resolve must not become a bypass for socket/principal/receipt fencing.

## Runtime reply agreement (runtime owns implementation)

`{status:{available:bool,running:bool,binding:HostBrowserBinding|null,
mode:"agent"|"human"|"private",controller:UUID|null,tabs:UUID[]},value?:...}`.
Status without an attachment may use nil `attachment_id` as noted above.
RequestOffer returns `value:{type:"offer",sdp}` with full ICE gathering.
Do not expose SDP/ICE, pixels, text, private tab metadata or cached secret payloads
in agent-visible history, durable receipts, generic events or another principal's
response. Reply scoping, runtime tombstones/leases and worker fencing are runtime
owner obligations; the protocol/Vessel adapter cannot establish their success.

## Verification ownership

No Rust builds/tests/coverage or commits are run by this task, per parent gate.
Protocol, adapter and transport regression tests accompany changes for the parent
to run after integration. Formatting/static diff inspection are not passing tests.

Input status exposes the acknowledged attachment sequence for safe remount on the
same socket. Compact input receipts retire into a fixed 2 MiB conservative hash
bitset for the runtime lifetime: retired IDs cannot dispatch again; a collision
refuses rather than admitting an uncertain replay. This is a bounded no-false-
negative tombstone filter, not an exact historical reply cache. Old bindings are
invalid after process/attachment replacement. Signaling replies remain scoped to
the attachment, and their full payloads never enter durable history.
