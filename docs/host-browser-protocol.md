# Host browser protocol

The source of truth is [host_browser.rs](../crates/voyage-protocol/src/host_browser.rs). This is the Voyage-owned browser on the Vessel host, separate from the opt-in local Browser executor. Both Helm clients send `VoyageCommand::HostBrowser` over their authenticated duplex Vessel socket. Vessel attaches private `HostBrowserSocket` provenance and the existing process grant; public JSON cannot choose a socket or principal. The runtime checks grant rights and revocation on every operation.

`HostBrowserBinding` carries `incarnation`, `browser_id`, `attachment_id`, `tab_id` and document, viewport, controller and capture epochs. All IDs must be non-nil for a bound operation and all epochs positive. Status may return a nil attachment ID before Attach. IDs are fences, never credentials. Socket loss delivers a private cleanup notification, invalidates its attachments and does not resume agent control.

| Operation | Right | Effect |
| --- | --- | --- |
| `status` | Observe | Read bounded browser status. |
| `start` | Execute | Launch with exact incarnation and expected revision. |
| `attach`, `detach` | Observe | Admit or remove one viewer on its authenticated socket. |
| `mirror {binding,since,format?}` | Observe | Read compressed DOM events and cursor; no mutation ID or durable page content. |
| `control {binding,mode}` | Execute | Select agent, human or private authority with a control fence. |
| `input {binding,sequence,input,claim?}` | Execute | Apply one typed human action with a consecutive attachment sequence. `claim: true` fences agent control and applies a first ordinary interaction atomically. |
| `receipt` | Observe | Query an exact command identity without cached secret payload. |
| `close` | Execute | Close the supervised browser and observe cleanup. |

Input variants are `history`, `click`, `surface_click`, `fill`, `select`, `wheel`, `upload`, `frame_element`, `download`, `key`, `text`, `scroll`, `resize`, `dialog`, `navigate` and `tab`. The optional `claim` flag is valid only for click, surface click, wheel, history, navigation and tab actions, including those element actions in a child frame. The worker retains the first target across its control fence and refuses if the page or target changed; it never repeats an uncertain action. A normal claim keeps other viewers connected. Private control remains an explicit `control` operation that excludes them. Element actions use a positive recorder node ID. `frame_element` wraps one of those element actions with a non-nil frame ID; the ID changes on frame navigation and is resolved only within the selected page. A surface click uses integer x/y fractions from 0 to 10,000 within a canvas/video/iframe element. Text is at most 16 KiB, uploads and returned downloads at most 2 MiB, navigation HTTP(S) only, and resizing 320–3840 by 240–2160. Structural validation is followed by live worker checks for authority, network policy and element state.

The mirror reply contains `{encoding:"gzip",data_base64,cursor,reset,latest,visuals,frames}`. The gzip body is a bounded rrweb event array. `reset` requires a full snapshot; subsequent reads use `since=cursor`. Each frame entry has `frame_id`, optional `parent_frame_id`, `host_node_id`, its own compressed event array, cursor and reset flag. Per-viewer frame cursors are held only in the live worker. A stale cursor, page change or control change resynchronizes instead of replaying input. Visual fallback items carry an element ID, position, dimensions and bounded JPEG bytes. The task page has no direct Helm channel. Replay iframes have no website script execution or network authority.

The optional mirror `format` is `css_chunks_v1`. Omission preserves the legacy gzip reply and request shape. Helm requests the format only when the live status `mirror_formats` list advertises it; Voyage derives that list from the actual retained worker's status, not the installed Core version. A format requested from a worker that does not support it is refused before dispatch. Existing voyages may retain an older worker after an upgrade and continue using legacy mirrors.

For `css_chunks_v1`, the top document and mirrored child frames use `{encoding:"gzip-chunks",format:"css_chunks_v1",chunks:[...],total_bytes,...}` with the usual cursor, reset and frame metadata. All chunks arrive in one bounded reply; there is no continuation operation or transfer identity. Each base64 gzip chunk decodes to at most 512 KiB, with at most 16 chunks. Compact payload and expanded logical event data each remain within an 8 MiB total across the top document and child frames. The existing 2.2 MB private-pipe and 2.8 MB outer wire-reply bounds remain; legacy event arrays remain bounded to 3 MB. The decoded payload carries events and a CSS dictionary; references at recognized CSS locations restore the complete captured CSS before replay. The viewer validates the whole reply, including child frames, before replacing a snapshot or advancing its cursor. Invalid chunks, incomplete data or expansion beyond the bound fail the observation without applying a partial page. Formatting and dictionary references confer no execution or network authority. Size refusals `page_too_large` and `mirror_limit` may appear as fixed, allowlisted mirror-observation diagnostics; they do not classify a prior effect as safe to repeat.

Effect IDs have exact deduplication. Input uses a bounded live receipt ledger plus runtime tombstones. A timed out or disconnected effect can be unknown, never safe to retry automatically. The worker's private protocol is documented in [its contract](../voyage/browser/CONTRACT.md).
