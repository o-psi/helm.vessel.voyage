## Discovery and interaction model

The palette is a projection of active keymap command entries: it excludes `hidden` commands and its own opener, groups categories, carries descriptions and computed key hints, and promotes suggested actions under Suggested. Availability therefore depends on route, focus, configuration, model and loaded plugins; a static list is not a guarantee every row appears at once. `/` autocomplete at composer start merges registered local slash commands with server commands; skill-sourced server commands are explicitly excluded there and get a separate skill picker. `@` completion merges files, non-primary visible agents, reference aliases and MCP resources, with fuzzy ranking and ten-item truncation. Commands are actions, not all slash aliases.

[packages/tui/src/component/command-palette.tsx](https://github.com/anomalyco/opencode/blob/95daf90670b7c039c436c85537da5fbfe2205b41/packages/tui/src/component/command-palette.tsx); [packages/tui/src/component/prompt/autocomplete.tsx:395](https://github.com/anomalyco/opencode/blob/95daf90670b7c039c436c85537da5fbfe2205b41/packages/tui/src/component/prompt/autocomplete.tsx#L395-L525); [packages/tui/src/keymap.tsx](https://github.com/anomalyco/opencode/blob/95daf90670b7c039c436c85537da5fbfe2205b41/packages/tui/src/keymap.tsx).

**Defaults are contextual:** leader is `Ctrl+X`, palette `Ctrl+P`; `Tab` cycles agents in the composer but changes focus/selection in dialogs and diff view. `Ctrl+C` can clear nonempty input, whereas exit is also bound to it globally. `Esc` can close a modal, leave shell mode, reject a question, or contribute to a double-press interrupt. Never interpret the raw binding table without focus/handler predicates. Mouse capture defaults on; configurable attention is globally off despite notification/sound suboptions defaulting on.

## Action-by-action workflows and recovery

| Action / entry | Focus, outcome and defaults | Recovery, safety and evidence limits |
|---|---|---|
| Start new / clear | `/new` (`/clear`) navigates home and clears dialogs; leader+n. | “Clear” is navigation, not a claim that existing history is deleted. |
| Find/resume session | `/sessions`, aliases `/resume`, `/continue`, leader+l; filterable list, today/date groups, pinned group, busy/retry spinner, quick-slot gutter; directory filtering initially enabled. | Top-level sessions are separated from children; stale/offline workspace recovery exists. No hands-on large-list latency result. |
| Pin / quick switch | Session-list `Ctrl+F` pin/unpin; leader+1…9 activate assigned quick slots. | `Ctrl+F` moves right in the composer and favorites in the model dialog; focus-specific hints matter. |
| Rename / delete | Rename via `/rename` or list `Ctrl+R`; list deletion `Ctrl+D`, repeated key confirms. Moving selection clears pending confirmation. | Errors toast; workspace-linked failure opens recovery dialog rather than claiming deletion. Delete is not undo. |
| Workspace navigation | “Manage workspaces” `/workspaces` is experimental-flag hidden; composer `/workspace` selects a workspace; copy worktree path only for a current worktree. | Do not equate hidden command with absent implementation or stable/default support. Workspace delete, restore/select, retry flows are explicit in dialogs. |
| Timeline / message menu | `/timeline` selects a user message; message menu offers Undo, Copy, Fork. Page/line/half-page/first/last/last-user and next/previous-message commands have contextual shortcuts. | Scrolling and selecting a historical message do not themselves revert it. |
| Fork | `/fork` opens fork-from-timeline; message action supplies message ID, creates another session, restores selected message prompt on navigation. | Alternate conversation is distinct from redo; a returned SDK result is assumed in some handlers, not proof of success-path robustness. |
| Child/subagent navigation | Parent, first child, next/previous child commands; child-list entries/task rows offer drilldown. Background foreground subagents uses experimental API (`Ctrl+B`). | Parent/child guards and modal guards apply. Do not equate background request admission with observed cleanup/completion. |
| Undo previous turn | `/undo`, leader+u: abort busy session first, find preceding user message before current revert marker, request revert, restore text/file prompt parts and move display end. | Transcript/file snapshot revert, **not editor undo** and not reversal of arbitrary shell/network side effects. The backend uses tracked file patches/snapshots; the source map below qualifies filesystem scope. |
| Redo | `/redo`, leader+r only when revert marker exists; next user marker advances revert, otherwise unrevert and clear prompt. | Redo is restoring reverted conversation state, not automatically rerunning a failed external action. |
| Compact | `/compact` (`/summarize`), leader+c; requires selected model and invokes summarization. | May use a provider; no compaction performed in audit. Missing model directs user to connect provider. |
| Share / unshare | `/share` (or copy existing URL) and `/unshare`; share disabled by config, unshare only if URL exists. | Copy / export | leader+y copies last eligible assistant text; `/copy` copies transcript; `/export` prompts export settings and can open editor or write a file, with success/error toast. | Review reasoning/tool inclusion and destination; clipboard/export can disclose content. Export is not session restore/import. |
| Enter text / multiline | Enter submits; Shift/Ctrl/Alt+Enter or Ctrl+J insert newline. Full movement, selection, deletion and editor undo/redo bindings in appendix. | Terminal modifier delivery varies; no Windows/macOS/SSH key fidelity claim. |
| Prompt history | Up/Down act as history only at appropriate buffer boundary and without autocomplete; preserve text, attachment parts and shell mode. | Cursor movement may consume first press before a history change. |
| Shell mode | `!` at input start switches composer mode; shell submit uses SDK session shell route; Backspace at start or Esc can leave mode. | Shell execution is an effect, not an inert annotation and not Helm's private human-terminal channel. |
| Attach context | `@` files/agents/resources and clipboard text/image; large text summarized into a display part while original content remains in prompt parts. | Summary is presentation, not redaction. Model capability and attachment-validation failures remain possible. |
| External editor | `/editor`, leader+e; expands summarized parts, uses `VISUAL` then `EDITOR`, temporary Markdown file, suspends renderer, spawns editor, restores renderer in finally. | Missing editor gives setup message; failed editor exit rejects. Temporary file cleanup attempted in finally. Not evidence of private capture isolation. |
| Stash | Palette Stash prompt / Stash pop / Stash list; list/delete binding `Ctrl+D`. Actions depend on nonempty prompt / stash availability. | Prompt storage separate from message history and conversation undo. |
| Submit / failure | Prompt handler selects ordinary prompt, slash command, or shell API; ordinary request initiation clears draft and appends history without awaiting completion. | Ordinary rejection shows an error toast, not automatic draft/agent/model restoration; no optimistic-message removal is implemented here. Earlier new-session creation errors return before draft clearing. Manual history recall is separate. |
| Interrupt | Hidden session interrupt bound Esc, busy only; two presses within five seconds invoke abort. Autocomplete/focus guards apply; shell mode exits first. | Request is fire-and-forget in this handler; double key is not evidence that tools stopped or effects rolled back. |
| Read streaming response | Event-fed text/reasoning/tool parts render in transcript with streaming code/Markdown components and sticky scroll. Tool states distinguish pending/running/completed/error. | Source path, not measured latency; disconnected stream should not be called a completed answer. |
| Reasoning display | `/thinking` toggles show/hide. Default **hide**, migrates legacy visibility preference; hidden state still shows “Thinking…”/summary title indicator. | Controls presentation of provider-supplied reasoning parts, not whether a model reasons or exposing unavailable internal reasoning. |
| Tool detail / generic output | Palette toggles; tool details initially true, generic tool output initially false; specialized renderers for shell/edit/write/task etc.; error text expandable on inline tools. | Denial/dismissal classification differs from generic failure. Do not treat collapsed output as absence of tool evidence. |
| Display settings | Sidebar auto, timestamps hide, conceal true, scrollbar false; animations/file context true, diff wrapping word, paste summary preference, theme/mode/lock and terminal-title toggles. | These are local/persisted presentation settings; none grants execution authority except separately named permission mode. |
| Diff review | `/diff`: working tree, main-branch comparison when branch metadata permits; ordinary Last turn selection lacks the message ID required by its backend; file tree, expand/collapse, hunk/file jumps, split/unified, single-patch, focus and help. | Read/review UI; no stage/commit/revert-hunk action found in inspected viewer command blocks. That is a bounded absence, not a repository-wide claim. |
| Permission decision | Inline request; Allow once / Always allow / Reject. Always opens a patterns confirmation; child-session rejection offers feedback while root rejection replies immediately; arrows/h/l, Return, shortcuts and Esc interpreted by active prompt. | Actual `once/always/reject` replies, not a plain chat “yes”; queued questions and permissions must not be conflated. Scope/default policy detailed below. |
| Answer question | Single/multiple choice, custom answer, multi-question tabs and final review. Up/down/j/k; left/right or Tab/Shift+Tab; digits 1–9 select, Enter commits/toggles, Esc rejects. | Custom-input editing takes precedence and Esc leaves edit state first. Single question can submit directly; multi-question answers reviewed before send. API failure is not successful answer delivery. |
| Status / debug | `/status`, `/debug`, toggle debug/console, heap snapshot; MCP/LSP/provider state in dialogs/sidebar. | Heap snapshots, crash stacks and copied reports may be sensitive. No diagnostics generated during this audit. |
| Crash / connection / update | Error boundary offers `c` copy report, `r` Restart (component reset), `q` Quit; update notices request application restart. SSE loop batches events and reconnects with capped exponential backoff. | Component reset is **not server process resurrection**. SSE outer catch can end loop; not a verified durable resume or exactly-once recovery guarantee. |
| Exit / suspend | `/exit`, `/quit`, `/q`; Ctrl+C/Ctrl+D/leader+q contextually; Unix terminal suspend Ctrl+Z where supported. | Renderer cleanup is separate from provider work lifetime; process-survival behavior depends on launch/attach path. No Helm/Vessel-style lifetime equivalence claimed. |

### Snapshot revert scope and subtle display defaults

- Terminal backend revert asserts not busy, gathers later patch parts, records/reuses a snapshot, restores prior snapshot where appropriate, applies patch reverts and stores the revert marker/diff. Unrevert restores the recorded snapshot and clears the marker; cleanup removes messages/parts past the marker. Snapshot tracking checks Git/project configuration, so do not promise universal file undo outside its supported context. [revert implementation](https://github.com/anomalyco/opencode/blob/95daf90670b7c039c436c85537da5fbfe2205b41/packages/opencode/src/session/revert.ts#L30-L136); [snapshot gating](https://github.com/anomalyco/opencode/blob/95daf90670b7c039c436c85537da5fbfe2205b41/packages/opencode/src/snapshot/index.ts#L160-L204).
- The session's `showThinking()` accessor is constant true at this pin, while `thinkingMode` governs collapsed/expanded rendering. Export/copy pass `showThinking()` into their options. Therefore “hide thinking” is **not a guarantee of excluding reasoning from export**; inspect export options independently. Generic tool output defaults **false**, unlike tool details (true). ## Comparative lessons for Helm (#271)

These are design recommendations, **not unverified claims that Helm lacks each capability**. Local comparator context: `docs/current-state.md` (read-only inspection), particularly scoped focus, notifications, streamed/tool outcome provenance and separate private execution surfaces. No Pi/Codex conclusions are fabricated from this OpenCode-only task.

1. **P0 — One action registry, many discovery surfaces.** OpenCode derives palette/slash/key hints from registrations and contextual bindings. Helm should audit command-family leaves against its actual registry, with hidden/disabled/experimental distinctions and aliases tested separately. Do not mistake a help list for complete coverage.
2. **P0 — Preserve safety semantics while improving access.** Keep permission responses, question answers, cancellation requests and observed cleanup visibly distinct. OpenCode's auto-approve toggle and persisted share consent deserve explicit scope warnings; Helm's machine-local policy and human-private capture boundaries must not be flattened into a global convenience switch.
3. **P0 — Recovery must describe what was restored.** Restoring a failed draft, resetting a UI error boundary, reconnecting an event stream, reverting snapshots and reviving a process are five different outcomes. OpenCode supplies useful concrete recovery affordances but source does not establish arbitrary exactly-once recovery.
4. **P1 — Contextual shortcut inspection helps dense terminal UI.** Which-key and live key hints expose focus-dependent behavior. Audit collisions deliberately: Ctrl+F cursor/favorite/pin, Ctrl+D delete/exit, Ctrl+C clear/exit, Tab agent/dialog/diff, Esc interrupt/reject/close. Show the active interpretation before destructive use.
5. **P1 — Separate editor history, draft stash, session undo and fork.** OpenCode has all four, with distinct state. Adopt explicit names and explanatory outcome text rather than one ambiguous Undo action. Never imply external effects are reversible.
6. **P1 — Diff review should be a complete journey.** Tree/patch focus, hunk/file movement, working-tree/conditional-branch source choice and split/unified layout form a substantial source-defined review surface, not proven usability. The normal Last turn route is incomplete without a message ID. Preserve evidence provenance and make “reviewed” state distinct from persisted approval or commit.
7. **P1 — Progressive disclosure without suppressing status.** Reasoning can be hidden while an activity indicator remains; tool summaries separate denial from failure and permit expansion. Helm should retain canonical text/provenance and stable completion labels while reducing visual noise.
8. **P2 — Ship extensions without misrepresenting baseline.** Diff, tips and which-key are bundled plugins here. In comparisons, distinguish default shipped feature modules, operator-disabled modules, experimental workspaces and arbitrary installed plugin actions.
