## Source selection and current owner boundary

The audited clean `beb0e01` LCOV contains 178 unique zero-count addresses in
`vessel/src/process_http.rs`, 187 in `vessel/src/main.rs`, 196 in
`vessel/src/process/accounts.rs` and 200 in `vessel/src/process/database.rs`.
These are candidate addresses, not estimated gains; aggregate instantiation
totals differ. The full denominator and reachable-production objective remain.

The largest remaining database blocks concern protected configured/bound
identity and transitions; this cohort does not exercise those deferred scopes.
Existing account, enrollment, late saved-authority, accepted-turn, cold-browser
and Handle/App cohorts stay intact. Existing public adapter tests assemble
selected routes themselves. This cohort instead launches the actual current
`env!("CARGO_BIN_EXE_vessel")` entrypoint, covering normal CLI dispatch and the
complete production gateway router/middleware assembly.

The fixed ordinary `local-serve` child and public gateway child use private
fixture directories and the actual executing UID. No real host service is
changed. A fixed nonexistent Voyage binary path makes accidental runtime launch
fail. Preseeded ordinary fixture registration projections are imported by the
maintained supervisor; exact matching private Unix socket peers answer only
Health, Snapshot, Events, History, Receipt and Controls. Every execution,
inference, tool, terminal or other mutation panics the peer. No executing Voyage
or real conversation journal is presented as qualified by these peers.

## Private resources, deadlines and coverage identity

Every child clears its environment, then receives fixed private HOME/XDG roots,
fixed PATH, two Tokio workers, a synthetic temporary credential key on private
tmpfs, and only the
actual parent `LLVM_PROFILE_FILE` destination for coverage. No human/provider
environment, credential, wrapper or startup customization is inherited. The
visible top-level `CARGO_BIN_EXE_vessel` declaration identifies the actual
instrumented entrypoint to the object audit. Adding this integration target adds
one current test object; the final object set must be derived from the current
Cargo targets, not a historical fixed count. Entry-point profiles belong to the
same current owned prefix and are not private `default.profraw` substitutes.

The fixture observes each long-lived child's PID/start/UID/executable inode and
the listener inode in that exact child's descriptor set. Signal delivery is
permitted only after the identity check; success requires reaping that child,
absent `/proc` identity and refused connection to its former listener. Supervisor
discovery must be removed; all owned peer request tasks are joined and their
Unix sockets are removed/refuse reconnect. Cancellation in panic Drop is only
best effort, never a passing cleanup observation.

Requests, response bodies, SSE buffers, peer counts, captured metadata and log
files have explicit bounds. Each request/phase/process retirement has a finite
deadline. Parent and child environments are separate. Private files are
nofollow, owned, single-link regular inodes; reads are capped even if a producer
grows a file after metadata inspection. Failed fixture roots/logs remain private
for diagnosis. Synthetic transient key material is retired. State removal on a
successful case follows the positive ownership/cleanup assertions.
