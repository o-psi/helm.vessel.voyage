## Fixture scope

`github/operator.rs` retains one shared dispatch body. Its public entry point
supplies the production private journal adapter and fixed-origin `Service::new`.
The private directory/service parameters have no runtime configuration or public
endpoint surface. The narrowly `cfg(test)` constructor lives in
`github/service_operator_fixture_tests.rs`, follows the same authority,
credential and owner validation, then substitutes the existing bounded owned
loopback client and private test journal. It does not weaken production policy,
credential checks, redirects, deadlines, publication approval, or receipt rules.

The positive default-journal test invokes the current libtest executable with
one exact child entry. Only that child receives fixture-owned HOME and XDG data
paths. The parent environment and caller's coverage profile configuration remain
unchanged. A finite wait, explicit kill/reap on timeout, a positive child exit,
and a completion witness establish the actual default dispatch. The inert
child entry contributes to default test counts; nested libtest summaries must
not be added again to the parent totals.

Other observations use the existing ten-second scripted loopback peer. Remote
publication is synthetic and stays on that listener. Agent inference responses
use the existing scripted provider. No live provider, paid budget, ambient
GitHub credential, external GitHub mutation or native deployment is exercised.
Git and terminal subprocesses remain confined to owned temporary workspaces;
terminal shutdown must be positively observed before claiming cleanup.
