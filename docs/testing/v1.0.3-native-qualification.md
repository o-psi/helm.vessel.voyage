## Compatible active upgrade: source `15f4ce3`

The [native checkpoint](https://github.com/o-psi/helm.vessel.voyage/issues/380#issuecomment-5924019476)
records the actual hosted nightly to local stable candidate upgrade, with identical
implementation/build-input contracts. The lifecycle transaction completed and exact
root/gateway readiness passed. The genuinely running UID1000 Voyage did not survive:
its durable run failed with `Execution policy prevented the run.` Systemd observed
the guardian and Voyage still alive when stopping the root supervisor. Protected
guardian completion subsequently recorded observed cleanup, successful child exit
and no guardian stop reason. Rollback/removal have not been invoked.

Source investigation identifies a separate supervisor lifetime dependency:
`process/service.rs` owns `scope_authority::Service`; dropping it aborts the
scope listener. `Agent::provider_wait` checks current execution authority every
100 ms, including during decoded provider events. Its root-authenticated scope
query fails closed while the supervisor listener is absent. An unchanged grant
must not become implicit permission to bypass this check during an upgrade.

The proposed repair moves each bound incarnation's metadata-only scope listener
into its independent guardian lifetime, with an exact session/incarnation socket
and lease binding. It retains current grant/revocation, execution epoch, protected
identity, kernel peer and token/nonce checks on every request. This source change
requires combined local verification and a new native artifact qualification; it
is not evidence that active continuity now passes. Old handles remain fail-closed
when their supervisor-owned listener is unavailable. No uncertain inference or
lifecycle request is replayed.
