# v1.0.3 ordinary participant and supervision coverage

Tracking: [#353](https://github.com/o-psi/helm.vessel.voyage/issues/353).
This source batch follows the ordinary attachment and server cohorts. It does
not change production behavior, the coverage inventory or exclusions. Execution,
coverage and hosted build follow-through belong to the coordinated release pass;
these test descriptions are intended contracts, not passing evidence.

## Participant contracts

The participant family uses a real independent parent journal/run and the actual
`ParticipantTool` transport. Its owned loopback Vessel protocol peer checks that
the exact assignment is canonical before receiving an Assign request. It records
only synthetic request bodies and operation names; no live account, provider or
remote Vessel is contacted.

The cases cover:

- Terminal result, exact retry and list; no second assignment effect.
- Uncertain delivery, original-ID retention, replacement refusal and permanent
  non-admission fencing without inventing a child run.
- Definite rejection, malformed observations and forged child identity.
- Detached cancellation monitoring: an admitted child retains its run/incarnation
  and becomes clean only after an exact observed cancellation receipt.
- Named endpoint and binding fences, payload collision, credential parent scope,
  read-only refusal, unattended approval refusal and authority revocation during
  an awaited approval before dispatch.
- Empty/invalid configuration and endpoint limits; positive configured runtime
  identity is exercised in a bounded owned libtest child, isolating the process
  resource-root OnceLock from concurrent tests.
- Malformed usage and invalid non-admission proof leave the last canonical
  observation unchanged. Top-level and nested bounded usage settle once; an
  unknown bounded delivery retains its reservation until permanent proof closes
  the same allocation. The private accounting observer verifies handoff, not
  journal durability; actual Goal durability belongs to the attachment cohort.
- Parent local completion retains unknown participant cleanup. Exact reconciliation
  releases the retained obligation; a later clean retained read succeeds after
  the loopback peer is observed retired, proving the read does not need an executor.
- Schema fences prevent runtime instruction disclosure and cancellation blocks
  admission before a canonical obligation or network request is created.

The peer owns and joins its request tasks on ordinary teardown. Cancellation
requested alone is never asserted to establish cleanup.

## Supervision contracts

The supervision family uses `RuntimeAgentSupervisor` over a real owned local
`SubagentRuntime` with a no-tools, read-only scripted executor. The executor has
no provider, shell, worktree or OS process effects. Its retirement counter proves
that executor future retirement was observed; it makes no external cleanup claim.

The cases cover live parentage/tree, exact message and follow-up delivery, filtered
inspection/replay and subscription, final-record independence, live cancellation,
queued cancellation before worker start, explicit terminal follow-up as a new
child, final parent immutability, unknown-ID versus operation-failure errors,
executor failure and shutdown refusal. Bounded history eviction and stale/foreign
cursors remain distinct from the retained final record. Controlled broadcast lag
produces cumulative transport-loss notices with nil agent identity, preserving
runtime event sequencing rather than inventing lifecycle history.

Retained projections preserve identities, task, result/error, progress, worktree
and elapsed-time bounds, including missing/backward timing and all status classes.
The third-party inspect-only fallback explicitly has no history contract; the
unavailable supervisor has no fictitious tree, event or execution authority.

## Remaining classification

These ordinary fixtures are not native cross-Vessel execution or real provider
qualification. Native ownership/privileged identity work is v1.1.0 scope. HTTP
partitions and malformed/refused responses here establish parent retention and
safe refusal, not remote cleanup. Positive durability of delegated Goal accounting
uses the separately measured journal/attachment cohort, not the synthetic
accounting observer. Transport credential/storage/platform-specific cases retain
their existing transport tests and native verification obligations. Resource-root
OnceLock second-initialization refusal and extreme u64 event-loss saturation are
in-process boundary cases, not release behavior established by these journeys.

The current-source coverage audit must identify any remaining reachable lines
within this family after execution. No remaining branch is excluded or labelled
unreachable merely because this source batch has not exercised it.
