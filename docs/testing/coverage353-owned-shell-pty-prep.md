## Prepared whole API journeys

Ten managed-shell parents exercise cancelled/denied approval admission before
markers/jobs, held approval with authority loss before spawn, actual exit and
bounded capture, concurrent output/cancellation, same-session descendants
retaining pipes, timeout and dropped-future cleanup, shutdown closing admission,
clone/resource retirement, and refused current-run synthetic private environment.
Only fixed harmless commands and fixture-only canaries are used.

Ten PTY parents exercise two exact named/selected identities and isolated input,
name/ID/schema/CWD/size refusal preserving a live sibling, actual capacity then
observed close/replacement, the existing production-used post-spawn seam retaining
a real failed child, bounded Unicode capture/cursor and typed dropped-byte gap,
synthetic human attach with permanent model privacy and a working sibling,
cancelled/oversized input with no suffix replay, typed private screen resize,
exact terminal interrupt/retirement preserving the sibling, and zero-budget busy
shutdown retaining obligations until a later observed shutdown.

The post-spawn callback is the existing used source seam; it supplies a failure
after an actual child exists, not a fake process. Scripted approval/authority
objects exercise real await/current-policy boundaries. No lifecycle receipt,
canonical conversation, other platform security or native production claim is
inferred from these tool-level fixtures.

## Isolation, cleanup and pending gate

Each parent reexecutes exactly its maintained test entry in an env-cleared ordinary
Linux child with private HOME/XDG/account-wide resource ledger and fixed PATH.
Only the actual LLVM profile destination is inherited. No human credential,
private terminal input, service, provider, browser or privileged identity is read
or changed. Child logs are private/bounded and retained on failure. The shared
helper is compiled once and reused, with a thirty-second parent bound.

Actual PTY child/session/start/UID witnesses are observed, not invented. Cleanup
uses the production SessionIdentity/pidfd/drain/wait path and must report an empty
observed result before retirement; requested termination, dropped future or
leader exit alone is insufficient. Test assertions do not publish canary input or
captured private screen data. Root/user grant and Linux session accounting remain
existing authority boundaries, not OS containment or proof about escaping tasks.

Source formatting/diff checks are separate from execution. Independent review,
one next coordinated source-final coverage/current-object measurement, compact
summary, normal Main publication and hosted build follow-through remain required.
No tests/Cargo/Main/target/native effects were performed during preparation.
