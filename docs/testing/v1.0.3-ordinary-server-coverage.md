# Ordinary server coverage batch for v1.0.3

This batch supports [#353](https://github.com/o-psi/helm.vessel.voyage/issues/353).
The starting evidence is the retained audited
`v103-browser-boundary-corrected/summary-current.json`. It reports 15/268
covered lines for `voyage/src/server.rs` and 225/523 for
`voyage/src/server/commands.rs`. The new sources have not been executed or
measured when authored. They do not establish 100% coverage or release readiness.
The coordinated workspace run must compile, execute and audit them before
updating `coverage/latest.json`.

The child fixture invokes the current libtest executable with one exact driver
test. It sets only fixture-owned HOME/XDG paths and preserves the caller's
`LLVM_PROFILE_FILE`; it does not create a competing Cargo target, change the
parent environment, read a developer login, or run another build. Every synthetic
HTTP listener is owned by the fixture. Child handles are tracked before effects
and force-retired on failed fixture teardown; that fallback is not runtime
cleanup evidence.

## Remaining classifications

- Native privileged launch, bound projection, reviewed configuration digests,
  cross-UID/private-pipe handoff and guardian-authorized prior-scope recovery are
  outside this ordinary-positive batch. Their v1.1.0 work remains parked. No root
  identity is simulated and no native positive claim is added.
- Authenticated GitHub publication, real participant destinations, real provider
  service behavior and browser worker rendering/navigation need their own approved
  or owned external fixture. Local refusal/reference routing is exercised here;
  external success is not inferred.
- The post-translation `WorkflowSubmit` match arm and the impossible success arm
  inside the model helper's error branch are structurally unreachable for the
  preceding dispatch/match construction. The successful translation and helper
  success/error paths are covered by the new cases; unreachable panics are not
  invoked to inflate totals.
- Non-Unix branches are not reachable in this Linux measurement and still need
  actual supported-platform verification before platform claims.
- Arbitrary kernel allocation, filesystem durability and concurrent external
  mutation failures are not established by this fixture. Existing bounded
  storage/cleanup checks remain authoritative; any residual reachable line/region
  gaps must be identified from the next audited report and assigned meaningful
  fault fixtures or retained explicitly as unfinished.

No coverage exclusion or denominator is changed. Passing this batch, when
verified, does not close remaining reachable production gaps elsewhere in #353.

The shared test-only helper is named `family_fixture_tests.rs` so the existing
standard test-source exclusion recognizes it. This naming correction precedes
measurement; no production file is hidden or prior source inventory removed.
The Vessel account child clears inherited environment variables, preserving only
PATH and LLVM_PROFILE_FILE before setting its private HOME/XDG fixture paths.
