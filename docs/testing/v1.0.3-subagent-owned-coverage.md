# v1.0.3 ordinary owned subagent coverage

Tracking: [#353](https://github.com/o-psi/helm.vessel.voyage/issues/353).
This continues the ordinary participant/supervision source cohort. It does not
change production behavior or coverage exclusions. Execution and coverage remain
pending the coordinated release pass; this document records intended assertions.

## Durable runtime contracts

The runtime family creates private temporary completion coordinators, two exact
run ledgers, a persistent agent tree and a scripted no-tools worker. The worker
performs no provider, terminal, subprocess or Git effects. Its retirement counter
observes only its own future retirement, without making external cleanup claims.

The cases cover:

- Exact registration before agent execution; immediate-parent ownership inheritance
  and shutdown obligations filtered by the original run reference.
- Cross-run and legacy parent adoption must be explicit. A live adopted parent
  cannot silently start another execution. A terminal adopted parent can start a
  new owned child whose cancellation token does not inherit an old cancellation;
  same-run children still refuse a cancelled parent.
- Foreign or absent persistent coordinators and unowned live follow-up refuse
  before new worker publication. Inbox follow-up retains the original owner.
- In-memory terminal state is insufficient. Missing durable records, live durable
  records, mismatched run references and failed terminal persistence retain the
  exact pending shutdown obligation until the same terminal record is stored.
- Archived final records are readable without replay. Corrupt archives block exact
  reads and the owning completion ledger's read; absence of an active control is
  not used as evidence that a previous ledger obligation completed successfully.
- Startup refuses a missing coordinator, missing ledger or absent ledger obligation
  before recovery/archive mutation, preserving the original record bytes.
- Valid owned and legacy retained records recover as interrupted, keep their prior
  progress and remain unsuccessful. The executor is never restarted, and the owned
  ledger remains incomplete.
- Failed agent-tree publication after ledger registration leaves a missing unresolved
  obligation; no worker starts and completion cannot be sealed as successful.
- A sealed ledger refuses registration before agent-tree/event/worker publication.

Temporary record corruption is confined to owned fixture stores. Preserved bytes
are restored before fixture teardown, with no automatic execution replay.

## Child assembly contracts

The build family validates the complete finite ancestry before selecting the
nearest workspace. Missing ancestors, duplicate identities and cycles fail even
when a nearer workspace exists. Explicit canonical read and write delegation must
both contain the requested workspace before implicit workspace roots can be added;
missing roots, sibling paths and Unix symlink escape refuse.

Actual `CliSubagentExecutor` refusal cases have owned loopback listeners and assert
that runtime unavailability, insufficient workspace delegation and inherited parent
revocation produce no provider POST. Positive cases execute the actual child agent
against a no-auth OpenAI-compatible loopback fixture and check captured model,
clamped output budget, exact allowed tool set and selected child input.

The public managed builder is exercised in a bounded owned libtest child, isolating
the resource-root OnceLock. It creates the actual persistent/coordinated owner,
uses its updated model, archives the completed child and drains the runtime. No
live account or credential environment is used; Git discovery is confined to the
owned temporary workspace, and no Git mutation occurs.

## Remaining classification

These are ordinary durable/data/runtime tests. Native Root/system identity remains
v1.1.0 work. Real providers, terminal/process cleanup and real Git worktree effects
retain their separate authority and qualification requirements. Extreme allocation,
OS filesystem errors and event-channel/storage failures need exact fixtures where
reachable; they are not newly excluded or reclassified as unreachable. Final
coverage must audit this family after execution against current source. Passing
compilation alone would not establish these behavioral assertions.
