# Zero-viewer capture observation preparation (#333)

This source cohort completes the missing idle interval in the existing Native/CUA
qualification programme. It is not a deployed pass. [#333](https://github.com/o-psi/helm.vessel.voyage/issues/333)
and [release #375](https://github.com/o-psi/helm.vessel.voyage/issues/375) remain
subject to actual source-qualified client/site/privacy/cost/cleanup evidence.

The existing Native **Disconnect viewer** control retains its mount and private
transport context; **Check browser status** uses normal observation-only reconnect.
This is distinct from Close viewer/disposal. The driver closes only Web A's dock,
disconnects Native A, waits for the acknowledged exact detach, and samples browser
A while B remains independent. It reconnects on the same Native page with a fresh
confirmed Attach on the same browser/incarnation; actual parsed Start/Close
request counters must not increase. Web A's normal dock reopen has its own fixed
proof. No launcher/token is reused, no extra page or private reopen is consumed,
and the original nine active windows/45-second requests/600-second job stay intact.

The worker's private metadata contains no URL, DOM, input, frame identifier or
credential. It records worker/browser/source identity, sequence/time, liveness,
zero viewers and recorder-stop acknowledgement. The source-created recorder and
its global slot are immutable; repeat initialization retains that closure. Stop
acknowledges actual inactive recording and empty queued capture. A missing recorder
observed in a frame means that source recorder is absent; undefined, failed,
detached, inaccessible or concurrently superseded acknowledgements are not promoted.
No public status fields or execution authority are added.

Publication is serialized. A joining viewer invalidates previous idle proof
before joining; inability to invalidate gives the existing recognized
`observation_unavailable` pre-effect refusal. This is bounded resource failure,
not a new permission or authority decision. Metadata writes are automatic inside
the existing private worker root, not human benchmark setup or per-mirror disk IO.
Close publishes an unavailable/running-false observation. Writer failure never
sets a successful stop flag.

The independent read-only host probe pins the actual owned Chromium root and
guardian PID/start/program/profile ancestry throughout the interval; Node liveness
and a stored boolean are not OS browser-liveness proof. It also pins PID/start/browser and the source hash
against the configured program and actual argv; private file/root/slot and source
inodes stay pinned throughout ten seconds. It neither reads page data nor sends
status/mirror/control commands. A timer alone, stale file, PID0, missing recording
ack or changing sequence cannot qualify. Concurrent host cost observation retains
its actual ledger scope; shared routing leaves are not relabelled browser-only
idle CPU. The interval establishes a selected browser's capture pause, not a
universal promise about website scripts, OS egress or browser suspension.

Prepared contracts include source recorder stop/immutable repeat installation;
real sandboxed worker disconnect/rejoin without closing Chromium; missing,
failed, stale acknowledgement and unsafe metadata refusal; exact private-probe
schema; and idle/reconnect oracle counters. Source parse/diff checks are separate
from execution. Root owns the coordinated final checks, updated asset inventory,
publication/hosted build, actual installed worker/helper/Web pins and the live
qualification. No tests/build/native effects ran during preparation.


Recorder capture starts disabled and requires a private-pipe capability and
monotonic generation. Neither key nor DOM/frame data enters metadata/status or
receipts. Website scripts cannot restart Voyage's recorder through exposed drain.
Stop invalidates older enables/drains and waits boundedly for earlier mirror
work; timeout or unsettled/uncertain capture prevents a positive acknowledgement.
Late mutation callbacks from an older recording generation are ignored.
The Native status-recovery path now decides attachment after fresh Status;
an observed NIL attachment reconnects without Start on the same owned page.
